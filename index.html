First, the most important idea in this guide先说这份指南里最重要的一件事

You were hired as a "Data Engineer." Your colleague is a "Software Engineer." Someone else is an "AI Engineer." These are labels on an org chart, and they get renamed every few years.

你的岗位叫"数据工程师"，同事叫"软件工程师"，另一个人叫"AI 工程师"。这些只是组织架构图上的标签，每隔几年就会换一批说法。

The titles change. The foundations don't. Everyone is standing on the same bedrock — how a machine computes, how data is stored, how two computers talk, how work gets deployed and kept safe.

头衔会变，地基不会。所有人踩的是同一块岩层——机器怎么计算、数据怎么存储、两台电脑怎么对话、代码怎么上线并保证安全。

An AI can now write a SQL query, a React component, or a Python script faster than you can. What it cannot do is know whether the answer is right. That judgment comes from understanding the layer underneath — and that's exactly what this roadmap builds. Learn the bedrock, and any title becomes reachable.

今天的 AI 写一条 SQL、一个 React 组件、一段 Python 脚本，都比你快。但它做不到的是判断这个答案对不对。这份判断力来自你对底下那一层的理解——而这正是这条路线图要建立的东西。地基打好了，任何头衔都在射程之内。

🧪 The lab analogy🧪 实验室类比

Every concept is first explained as something you've already done at a bench. Read this first — it's the hook your brain hangs the rest on.

每个概念都先用你在实验台上做过的事来解释。先读这部分——它是你大脑挂住后面所有内容的那个钩子。

▶ The animation▶ 动画演示

Press Replay on any diagram to watch data actually move. Concepts like "a request" or "a pipeline" only click once you see them in motion.

点任意图上的 重播，看数据真的动起来。"一次请求""一条管道"这类概念，只有看见它在动才会真正明白。

✓ The quiz + lab tasks✓ 自测与实操任务

Answer the check questions honestly, then do the hands-on tasks. Ticking a box updates the progress bar at the very top of the page.

老实回答自测题，然后动手做任务。每勾一项，页面最顶端的进度条就会往前走一点。

One rule above all: type the code yourself. Copy-pasting feels productive and teaches you nothing — the same way watching someone else pipette does not make you good at pipetting. Break things on purpose. Read the error message. That is the entire job.

最重要的一条规矩：代码要自己敲。复制粘贴让你觉得很有效率，但什么都学不到——就像看别人移液并不会让你自己移得准。故意把东西弄坏，然后认真读报错信息。这基本上就是这份工作的全部。
